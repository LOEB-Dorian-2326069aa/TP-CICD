# Fiche de Mise en Production — `v1.1.0`

- **Date prévue :** 2026-11-19
- **Version déployée :** `v1.1.0` (version précédente : `v1.0.0`)
- **User Story livrée :** US-42 — Déclaration du stock producteur et blocage des commandes en dépassement.
- **Approbateur Production :** Lead Dev / Mainteneur habilité (via GitHub Environment `production`).

---

## 1. Contenu de la release
- Ajout de la route `PATCH /products/:id/stock` permettant aux producteurs de mettre à jour leur stock disponible (`#1`).
- Ajout du contrôle transactionnel (`FOR UPDATE`) et de la décrémentation automatique du stock lors d'un `POST /orders`, avec retour `HTTP 409` et message explicite si la quantité demandée dépasse le stock (`#2`).
- Publication automatisée des images Docker taguées sur GHCR et ajout du workflow de rollback rapide (`#3`).

---

## 2. Analyse des risques spécifiques à cette livraison
- **Concurrence sur un même produit :** Deux restaurateurs commandent simultanément le dernier lot disponible -> *Mitigé par verrou transactionnel SQL `SELECT ... FOR UPDATE`.*
- **Régression sur les 1 200 produits initiaux :** Risque que certains produits aient un stock nul ou invalide -> *Vérifié en staging sur le jeu de 1 200 produits générés par `db/init.sql`.*
- **Besoin de retour arrière rapide :** Aucune suppression de colonne en base (règle *Expand & Contract*), garantissant la compatibilité ascendante avec `v1.0.0`.

---

## 3. Critères Go / No-Go
- [ ] Tous les tests unitaires et d'intégration passent au vert dans la CI (`npm test`).
- [ ] L'image `ghcr.io/<owner>/<repo>:v1.1.0` est publiée et signée par le commit de release.
- [ ] Le déploiement sur `staging` (`preprod`) est vert et le test de fumée (`GET /health`) retourne `v1.1.0`.
- [ ] Le test manuel/curl en staging confirme le refus d'une commande supérieure au stock (`HTTP 409`) et l'acceptation d'une commande valide (`HTTP 201`).
- [ ] Déploiement effectué hors créneau interdit (pas le vendredi après 16h).

---

## 4. Test de fumée (Smoke Test) réalisé en Staging & Production
1. `curl -s http://localhost:3000/health` → Vérifier `"status": "ok"` et `"version": "v1.1.0"`.
2. `curl -s http://localhost:3000/products | head -c 200` → Vérifier le retour des produits avec le champ `stock`.
3. Déclarer un stock de `2` sur le produit `#1` (`PATCH /products/1/stock`), tenter une commande de `5` (`POST /orders`) → Vérifier le rejet `HTTP 409` avec le message explicite.

---

## 5. Plan de retour arrière (< 5 minutes)
1. **Déclencheur :** Échec du *Smoke Test* `/health` ou erreur `500` sur `POST /orders` après déploiement.
2. **Action :** Lancer le workflow GitHub Actions **`Rollback Production (< 5 min)`** (`rollback.yml`) avec le paramètre `target_version = v1.0.0`.
3. **Durée estimée :** ~1 min 30 (pull de l'image `v1.0.0` déjà présente sur GHCR + redémarrage conteneur + vérification `/health`).
4. **Impact données :** Les commandes validées avant le rollback restent conservées en base ; la base PostgreSQL reste 100 % compatible avec `v1.0.0`.
